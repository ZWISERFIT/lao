## 二、P0-2：激活 CPU→自动恢复闭环

### 实现

在 `ris/agent.py` 的 `RecoveryExecutor` 新增 `recover_cpu()` 方法 + 模块级持续跟踪：

**五步闭环（严格遵循 RecoveryEngine 铁律「禁止只 restart 不验证」）：**

1. **Detect（持续检测）**：CPU 连续 ≥3 帧 > 90%（约 90s·跨 30s 检测周期累积），状态写 `ris/state/data/cpu-sustained.json` 持久化，不因单帧误触发。
2. **Classify**：`cpu_sustained`
3. **Recover（安全恢复）**：识别 top CPU 进程（`psutil.process_iter`·记录到 detail）+ 对空闲 `npm exec @agentmemory` mcp 进程 SIGHUP 温和降级（不碰 gateway/lao-router/agent 主进程）。
4. **Verify（验证）**：恢复后重新采样 `/proc/stat`，CPU 需回落 <70% 才通过（铁律：不验证不 Record）。
5. **Record**：`cpu_recovery` 事件（severity=warn）append 到 ris-events.jsonl，携带 `top_processes` / `peak_cpu` 供审计。

### 证据（真实生产触发·非 mock）

运行中的 `ris-monitor.service` 自主触发 3 次完整闭环：

```
15:47:08  cpu_recovery  peak=95.0  top=python3   (首次·验证闭环)
15:48:18  cpu_recovery  peak=97.1  top=node      (openclaw 80.3%)
15:50:00  cpu_recovery  peak=99.0  top=node      (服务重启后自主触发)
```

样例事件（完整五步字段）：
```json
{"layer":"ris","event_type":"cpu_recovery","agent_id":"system","status":"recovered",
 "severity":"warn","detail":{"classified":"cpu_sustained","attempts":1,
 "verified":true,"recorded":true,"detect":"cpu_sustained detected",
 "top_processes":[{"pid":280624,"name":"node","cpu_pct":80.3,"cmd":".../openclaw/dist/index.js"},
                  {"pid":199997,"name":"python3","cpu_pct":17.9,"cmd":"python3 -c"},
                  {"pid":3383726,"name":"YDService","cpu_pct":15.7,"cmd":".../YDEyes/YDService"}],
 "peak_cpu":99.0},"ts":"2026-08-15T15:50:00.320367+00:00"}
```

### 关键变化

- `RIS_EVENT_TYPES` 新增 `cpu_recovery`（recovered 对偶信号）。
- `run_once()` 主循环接入：`if cpu_pct >= 80: recover_cpu(...)`。
- 状态文件 `cpu-sustained.json` 跨周期累积「持续」判据，避免单帧抖动误触发。

## 三、P0-3：RIS→LAO 数据桥

### 实现

新增 `ris/bridge.py`：`RISToLAOBridge` 类 + `sync_bridge()` 便捷入口。

**桥机制：** 把 append-only 的 `ris-events.jsonl`（RIS 1910+ 事件）聚合为结构化共享 JSON，供 LAO 路由决策 / Stella 审计 / 智囊团复盘消费——让 RIS 数据**进入决策闭环**而非只躺在日志。

**落盘位置（共享状态约定）：** `/home/agentuser/shared/state/ris-bridge.json`（原子写·`.tmp`+`os.replace`）

### 共享 JSON 结构

```json
{
  "layer": "ris",
  "schema_version": "1.0",
  "generated_at": "2026-08-15T15:50:33.539183+00:00",
  "window": { "since": "2026-08-15T04:14:58", "events_total": 1975 },
  "summary": {
    "events_by_type": { "session_bloat": 1311, "cpu_anomaly": 621, "mcp_leak": 11,
                        "lao_router_down": 4, "gateway_down": 3, ... },
    "recoveries": { "cpu_recovery": 3 },
    "provider_status": { "lao-router": "healthy" },
    "latest_cpu_pct": 100.0,
    "latest_mem_pct": 0.0
  },
  "recent_events": [ <最近 50 条 RuntimeHealthEvent> ],
  "active_alerts": [ <未恢复的 critical/error 最近 10 条> ]
}
```

### 关键语义

- **`summary.events_by_type`**：一键看到各事件类型累计（1910+ → 结构化）。
- **`summary.recoveries`**：恢复闭环成果计数（cpu_recovery=3 等）。
- **`summary.provider_status`**：成本链路健康（lao-router/direct 是 healthy 还是 down）。
- **`active_alerts`**：只保留未恢复的 critical/error（recovered 不告警·有 10 条上限）。
